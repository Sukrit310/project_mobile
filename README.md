# MoneyMate

แอป Flutter ภาษาไทยสำหรับบันทึกรายรับและรายจ่าย พร้อม Dashboard ประวัติที่ค้นหา/แก้ไข/ลบได้ สถิติพร้อมกราฟ และงบประมาณรายเดือน แยกหน้าจอ ส่วนแสดงผล และการเข้าถึงข้อมูลออกจากกัน มีคอมเมนต์ภาษาไทยอธิบายโค้ดและ [คู่มืออ่านโค้ด](docs/code-guide-th.md)

## หน้าตาและลูกเล่น

- โทนน้ำเงิน–มิ้นต์ พื้นหลังอ่อน การ์ดและไอคอนแยกสีรายรับ/รายจ่าย พร้อมเมนู Material 3
- ฟอนต์ **Noto Sans Thai** บรรจุในแอป จึงไม่ต้องโหลดฟอนต์จากเครือข่ายระหว่างใช้งาน ดูที่มาและใบอนุญาตใน `assets/fonts/`
- ปุ่มรูปตาบนการ์ดยอดสุทธิซ่อน/แสดงยอดทั้งสามบนการ์ด และคงสถานะเมื่อเปลี่ยนแท็บภายในเซสชันเดียวกัน รายการธุรกรรมยังแสดงยอดของแต่ละรายการตามเดิม
- ยอดเงินและการสลับแท็บมีแอนิเมชันสั้น ๆ โดยแสดงข้อความยอดจริงถึงสตางค์ทันที ไม่มีการคำนวณยอดระหว่างทางผ่าน `double` รองรับการตั้งค่าลดแอนิเมชันของเครื่อง
- ช่องกรอก ตัวกรอง แบบฟอร์ม และกล่องข้อความใช้สี/ระยะห่างร่วมกัน พร้อมรองรับจอแคบและการขยายตัวอักษร
- Dashboard 2.0 แยกยอดสะสมทุกเดือนออกจากรายรับ/รายจ่ายประจำเดือน มีสรุปงบจาก `BudgetRepository` จริง สถานะโหลด/ผิดพลาด/รอยืนยัน และปุ่มตั้งงบเมื่อยังไม่มีวงเงิน
- ทางลัด **เพิ่มรายจ่าย**, **เพิ่มรายรับ**, **ดูสถิติ** และ **ดูทั้งหมด** เปิดเส้นทางจริง ปุ่มเพิ่มรายการเข้าถึงได้จากทั้งสี่แท็บ แสดงรายการล่าสุดได้สูงสุด 5 รายการ และสรุปหมวดรายจ่ายสูงสุดจากข้อมูลเดือนที่แสดง

## รันและทดลอง

ติดตั้ง Flutter SDK ที่รองรับ Dart `^3.13.7` แล้วรันจากโฟลเดอร์โปรเจกต์:

```sh
flutter pub get
flutter run
```

เมื่อเปิดแอปจะแสดงหน้า Welcome ก่อน กด **เริ่มต้นใช้งาน** เพื่อเข้าสู่ Firebase Bootstrap หรือ Dashboard ตามแหล่งข้อมูลเดิม กด Back จาก Dashboard จะไม่ย้อนกลับ Welcome และการเปิดแอปใหม่จะแสดง Welcome อีกครั้งโดยไม่บันทึกสถานะข้ามรอบเปิดแอป

เมื่อยังตั้งค่า Firebase ไม่ครบ หลังเริ่มต้นใช้งานแอปจะแสดงหน้าตั้งค่า พร้อมปุ่มลองอีกครั้งและ **ทดลองด้วยข้อมูลตัวอย่าง** ต้องเลือกโหมดตัวอย่างเอง ข้อมูลโหมดนี้อยู่ในหน่วยความจำ หายเมื่อเริ่มแอปใหม่ และไม่ส่งเข้า Firebase

ข้อมูลตัวอย่างอ้างอิง **พฤศจิกายน 2026**: รายรับ ฿12,000 รายจ่าย ฿3,500 ยอดสุทธิ ฿8,500.00 รายการล่าสุดคือค่าอาหาร เงินเดือน และค่าที่พัก ส่วนโหมด Firestore ใช้เดือนปัจจุบัน และเมื่อไม่มีข้อมูลจะแสดงยอดศูนย์โดยไม่เติมข้อมูลตัวอย่าง

## เพิ่มรายการ

ปุ่ม **เพิ่มรายการ** เปิดฟอร์มที่ใช้งานได้จริง:

- ชื่อรายการตัดช่องว่างหัวท้าย ต้องยาว 1–80 ตัวอักษร
- เลือกรายรับ/รายจ่ายและหมวดหมู่ผ่านปุ่มไอคอน ทางลัดรายรับเปิดประเภทและหมวดเงินเดือนให้พร้อม จำนวนเงิน ฿ อยู่ส่วนแรกของฟอร์ม ส่วนการแก้ไขคงค่าประเภท/หมวดเดิม
- จำนวนเงินมากกว่า 0 และไม่เกิน **999,999,999.99 บาท** ทศนิยมไม่เกิน 2 ตำแหน่ง ไม่ใส่เครื่องหมายหรือจุลภาค
- เลือกวันที่ตั้งแต่ 1 มกราคม 1900 ถึงวันนี้

จำนวนเงินแปลงตรงเป็น `int` หน่วยสตางค์ เช่น 80.25 บาทเป็น `8025` โดยไม่ใช้ `double` ขณะบันทึกจะปิดการแก้ไข ปุ่มส่งซ้ำ และการย้อนกลับ หากล้มเหลวจะแสดงข้อผิดพลาดและเก็บค่าที่กรอกไว้ หากหมดเวลารอจะแจ้งว่ายังยืนยันผลไม่ได้ เพราะคำสั่งอาจถึงเซิร์ฟเวอร์แล้ว การลองอีกครั้งในฟอร์มเดิมใช้ document ID เดิม เพื่อลดการสร้างรายการซ้ำ บันทึกสำเร็จแล้วกลับหน้าที่เปิดฟอร์ม โดย Dashboard และประวัติรับข้อมูลใหม่ผ่าน stream เดียวกัน

## ประวัติ แก้ไข และลบรายการ

เมนูด้านล่างเปิด **หน้าหลัก**, **ประวัติ**, **สถิติ** และ **งบประมาณ** ได้จริง หน้า History มีตัวเลือกดังนี้:

- กรองเดือนและปี หรือเลือก **ทุกเดือน**
- เลือกทุกประเภท เฉพาะรายรับ หรือเฉพาะรายจ่าย
- ค้นหาจากชื่อรายการ โดยไม่แยกตัวพิมพ์ใหญ่/เล็ก
- แสดงรายการที่ตรงตัวกรองทั้งหมด เรียงใหม่ไปเก่าและแบ่งกลุ่มตามวัน พร้อมยอดรวมรายรับ/รายจ่ายของผลลัพธ์ที่กรองแล้ว
- แสดงข้อความเมื่อไม่พบรายการ และเลื่อนตัวกรองกับรายการได้บนจอเล็ก ขณะเปิดคีย์บอร์ด หรือเมื่อขยายตัวอักษร
- แยกข้อความไม่มีรายการเลยออกจากไม่พบตามตัวกรอง และแสดงกลุ่ม **วันนี้** / **เมื่อวาน** ตามวันปฏิทินในเครื่อง

ตัวกรองคงอยู่เมื่อ stream ส่งข้อมูลใหม่และเมื่อกลับจากฟอร์มเพิ่ม/แก้ไข เมนูของแต่ละรายการเปิดฟอร์มแก้ไขหรือขอลบได้ ส่วนปุ่มกระเป๋าเงินบน Dashboard เป็นทางลัดไปหน้างบประมาณ

การแก้ไขใช้ `TransactionFormScreen` เดิมผ่าน `initialTransaction` โดยเติมชื่อเดิม จำนวนเงินเป็นบาททศนิยมที่ไม่ใส่จุลภาค ประเภท หมวดหมู่ และวันที่ เปลี่ยนหัวข้อเป็น **แก้ไขรายการ** และปุ่มเป็น **บันทึกการแก้ไข** บันทึกด้วย ID เดิมและเก็บ timestamp เดิมครบถึงไมโครวินาทีเมื่อไม่ได้เปลี่ยนวัน รวมถึงรายการเดิมที่อยู่นอกช่วงวันที่สำหรับเพิ่มรายการใหม่ การเปิดแล้วกดยกเลิกตัวเลือกวันที่ไม่เปลี่ยนค่าเดิม; หากเลือกวันใหม่จะคงเวลาของวันเดิมไว้

`updateTransaction()` ใช้ Firestore `update()` จึงไม่สร้างเอกสารกลับขึ้นมาเมื่อรายการถูกลบไปแล้ว กรณีนี้ส่ง `TransactionNotFoundException` ให้ฟอร์มแสดง **ไม่พบรายการนี้แล้ว กรุณากลับไปตรวจสอบประวัติ** และเก็บค่าที่กำลังแก้ไขไว้

การลบต้องยืนยันผ่านกล่องข้อความที่แสดงชื่อและจำนวนเงินก่อน การยกเลิกไม่เรียก repository ขณะรอจะแสดงสถานะกำลังลบและป้องกันการส่งคำสั่งซ้ำสำหรับรายการนั้น แสดงผลสำเร็จเมื่อคำสั่งตอบกลับสำเร็จเท่านั้น; ข้อผิดพลาดให้ตรวจการเชื่อมต่อและสิทธิ์ ส่วน timeout ระบุว่ายังยืนยันการลบไม่ได้และรายการอาจถูกลบแล้ว ให้รอข้อมูลล่าสุดก่อนลองอีกครั้ง การลองลบซ้ำอ้างอิง ID เดิม ยอด Dashboard อัปเดตจาก stream หลังแก้ไขหรือลบ

โหมดตัวอย่างรองรับเพิ่ม/แก้ไข/ลบด้วย repository ในหน่วยความจำเช่นกัน การลบข้อมูลบน Firebase จริงต้องเผยแพร่กฎสิทธิ์ฉบับใหม่ตามหัวข้อ **กฎและการตรวจสอบ** ก่อน

## สถิติรายเดือน

หน้า **สถิติ** ใช้รายการจาก stream เดียวกับ Dashboard และประวัติ เลือกเดือน/ปีจากรายการ หรือใช้ลูกศรเลื่อนไปเดือนก่อนหน้าและถัดไปได้:

- แสดงรายรับ รายจ่าย สุทธิของเดือน และจำนวนรายการ โดยสุทธิของเดือนคือรายรับลบรายจ่ายเฉพาะเดือนที่เลือก ต่างจากยอดสะสมทุกเดือนบน Dashboard
- กราฟโดนัทแสดงสัดส่วนรายจ่ายตามหมวดหมู่ พร้อมคำอธิบายสี ชื่อหมวด ยอดเงินจริง และเปอร์เซ็นต์ หมวดที่มีสัดส่วนเล็กยังมีข้อมูลในคำอธิบาย
- กราฟแท่ง **แนวโน้มรายรับรายจ่าย** แสดงแท่งคู่ในแต่ละวัน: มิ้นต์คือรายรับ น้ำเงินคือรายจ่าย พร้อมจุดสีและยอดรวมแยกชนิด เลือก **รายสัปดาห์** หรือ **รายเดือน** จากเมนูมุมขวาได้ รายสัปดาห์แสดงจันทร์–อาทิตย์พร้อมลูกศรเลื่อนสัปดาห์และช่วงวันที่จริง หากสัปดาห์ข้ามเดือนจะรวมข้อมูลครบทั้งสัปดาห์ ส่วนรายเดือนแสดงแต่ละวันของเดือนที่เลือก เดือนปัจจุบันหยุดที่วันนี้หรือวันที่มีรายการรายรับ/รายจ่ายอนาคตเดิม
- จำนวนเงินทั้งสองชนิดรวมแยกกันด้วย `int` สตางค์โดยไม่หักกลบ กดแท่งเพื่อดูชนิดและยอดวันนั้น หรือเปิด **ดูยอดรายวัน** เพื่ออ่านรายรับและรายจ่ายครบทุกวัน รวมถึงวันที่เป็นศูนย์ วันที่มีแต่รายรับยังแสดงกราฟได้ รองรับการขยายอักษรและลดแอนิเมชัน
- ข้อสรุปแสดงหมวดรายจ่ายสูงสุดและจำนวนรายการจริง เปรียบเทียบเปอร์เซ็นต์กับเดือนก่อนเฉพาะเดือนที่สิ้นสุดแล้ว มีรายจ่าย และฐานเดือนก่อนมากกว่าศูนย์ หากข้อมูลไม่พอจะแจ้งตามจริง
- กราฟแท่งเปรียบเทียบรายรับและรายจ่ายของเดือนเดียวกัน พร้อมยอดเงินจริงแยกจากแกนกราฟ
- เดือนว่างแสดงยอดศูนย์และปุ่มเพิ่มรายการ ไม่มีการเติมข้อมูลตัวอย่างในโหมด Firebase
- เมื่อมีการเพิ่ม แก้ไข หรือลบรายการ กราฟคำนวณใหม่จาก stream โดยคงเดือนที่เลือก รวมถึงเมื่อลบรายการสุดท้ายของเดือนนั้น การกลับจากฟอร์มเพิ่มรายการคงเดือนเดิมเช่นกัน

`MonthlyStatistics` เก็บผลรวมเป็น `int` หน่วยสตางค์และสำเนาหมวดหมู่ที่แก้ไขไม่ได้ ส่วน `calculateMonthlyStatistics()` กรองทั้งปีและเดือน ไม่เปลี่ยนข้อมูลต้นทาง และรองรับหมวดหมู่เดิมทุกค่าที่บันทึกไว้ ใช้ `double` เฉพาะพิกัดและสัดส่วนของกราฟ ไม่ใช้คำนวณยอดเงิน

`StatisticsScreen` เป็น `StatefulWidget` เพื่อเก็บเดือนที่เลือก ใช้ `DropdownButton` และ `IconButton` สำหรับเปลี่ยนเดือน, `SingleChildScrollView` สำหรับเลื่อนทั้งหน้า, `LayoutBuilder` กับ `Wrap` เพื่อจัดยอดเงินลงมาเมื่อจอแคบหรือตัวอักษรใหญ่ ส่วน `ExpenseChart` และ `IncomeExpenseChart` เป็น `StatelessWidget` ที่รับยอดผ่านพารามิเตอร์แล้ววาด `PieChart`/`BarChart` จากแพ็กเกจ `fl_chart` โดยไม่เรียก Firebase เอง

## งบประมาณรายเดือน

หน้า **งบประมาณ** ตั้งและแก้ไขวงเงินรวมแยกปี/เดือนได้ แสดงวงเงิน ยอดใช้ไป ยอดคงเหลือ และ `LinearProgressIndicator` โดยยอดใช้ไปมาจากรายการประเภท `expense` ของเดือนที่เลือก รายรับไม่หักลดยอดนี้ และไม่เก็บยอดใช้ไปซ้ำในเอกสารงบ

- ใช้ถึง 80% เตือน **ใกล้ถึงวงเงิน**; เท่าวงเงินแสดง **ใช้ครบวงเงินแล้ว**; เกินวงเงินแสดง **เกินงบแล้ว** พร้อมยอดคงเหลือติดลบจริง
- แถบความคืบหน้าจำกัดอยู่ที่ 0–100% แต่ข้อความแสดงเปอร์เซ็นต์ใช้จริงที่อาจเกิน 100% งบศูนย์หรือไม่มีเอกสารแสดง **ยังไม่ได้ตั้งงบประมาณ** โดยไม่หารด้วยศูนย์
- ลูกศรและตัวเลือกเดือนเปลี่ยน subscription พร้อมล้าง snapshot เดิม จึงไม่แสดงวงเงินเดือนก่อนระหว่างรอข้อมูลเดือนใหม่ เดือนยังคงอยู่เมื่อรายการรับจ่ายเปลี่ยนหรือกลับจากฟอร์มเพิ่มรายการ
- ฟอร์มวงเงินใช้กติกาจำนวนเงินเดียวกับรายการ เติมค่าทศนิยมเดิมครบสตางค์ ปิดการแก้ไข/กดซ้ำ/ย้อนกลับขณะบันทึก และเก็บค่าเดิมเมื่อเกิดข้อผิดพลาดหรือ timeout การลองซ้ำใช้ ID เดือนเดิม
- หากมีหน้าอื่นเปิดทับขณะบันทึกสำเร็จ จะปิดเฉพาะกล่องงบเดิม ไม่ปิดหน้าที่เปิดทับ ข้อความ cache/pending แสดงแยกจากผลยืนยันสำเร็จ

`BudgetScreen` เป็น `StatefulWidget` เก็บเดือนและ stream งบ; `StreamBuilder<BudgetFeed>` รับวงเงินและ metadata; `BudgetEditorDialog` ใช้ `Form`, `TextFormField`, `AlertDialog` และ `PopScope`; `BudgetSummary` คำนวณด้วยจำนวนเต็ม ส่วน `BudgetProgress` แสดงสถานะและแถบพร้อมข้อความสำหรับตัวช่วยอ่านหน้าจอ

งบจริงใช้ repository แยกจากรายการที่ `users/{uid}/budgets/YYYY-MM` มี 3 ฟิลด์: `monthKey`, `limitSatang`, `updatedAt` บันทึกด้วย `set()` ที่ ID เดือนเดิมและ `FieldValue.serverTimestamp()` ตาม [คู่มือเพิ่มข้อมูล Firestore](https://firebase.google.com/docs/firestore/manage-data/add-data) โหมดตัวอย่างมีงบพฤศจิกายน 2026 เท่ากับ **฿5,000**, ใช้ไป **฿3,500**, คงเหลือ **฿1,500** และไม่เขียนข้อมูลนี้ลง Firebase

ก่อนใช้งบจริงต้องอัปเดตกฎตามหัวข้อ **กฎและการตรวจสอบ** ด้านล่าง หากกฎ remote รองรับเพียง transactions หน้างบจะแสดงข้อผิดพลาดสิทธิ์และปุ่มลองใหม่ แท็บอื่นยังใช้งานได้ตามเดิม

## คอมเมนต์และคู่มือโค้ดภาษาไทย

โค้ดใน `lib/` และ `test/` มีคำอธิบายภาษาไทยของหน้าที่และส่วนทำงานสำคัญ เช่น state, validation, stream, ยอดสตางค์ และสถานะ async รวมถึงไฟล์แพลตฟอร์มที่ดูแลเอง กฎ Firestore, `pubspec.yaml` และ lint config การปรับ Dashboard รอบนี้คงคอมเมนต์เดิมที่เกี่ยวข้องและเพิ่มคำอธิบายการคำนวณ/เปลี่ยนเดือนในส่วนใหม่

อ่านเส้นทางการทำงานและหน้าที่ของแต่ละส่วนได้ใน [คู่มืออ่านโค้ดภาษาไทย](docs/code-guide-th.md) ไฟล์ที่ Flutter สร้างอัตโนมัติ ผล build/cache และ JSON อธิบายในคู่มือ เนื่องจากตัวสร้างไฟล์จะเขียนทับคอมเมนต์และ JSON ไม่รองรับคอมเมนต์ในตัวไฟล์

## ตั้งค่า Firebase จริง

ตั้งค่า Android จาก `android/app/google-services.json` แล้ว: โปรเจกต์ **projectmoneymate**, application ID **com.example.project_moneymate** ใช้ Google Services Gradle plugin และ `FirebaseOptions` ที่ตรงกับแอปที่ลงทะเบียน จึงรัน Android ได้โดยไม่ต้องส่ง `--dart-define` หรือติดตั้ง Firebase CLI เพิ่มเพื่อโหลด config นี้

ตั้งค่าเว็บจาก `firebaseConfig` ที่ผู้ใช้ให้แล้ว โดยใช้ Web App ID ของ **projectmoneymate** แยกจาก Android สามารถรัน Chrome ได้ทันทีโดยไม่ต้องส่ง `--dart-define`:

```sh
flutter run -d chrome
```

ตรวจ Firebase จริงผ่าน REST API ล่าสุดแล้ว: **Anonymous Auth และการอ่านคอลเลกชันของผู้ใช้จาก Firestore ผ่าน** ได้ผลเป็นรายการว่าง ไม่มีการเขียนรายการทดสอบ และลบบัญชี anonymous ชั่วคราวที่สร้างเพื่อทดสอบแล้ว ผลนี้ยังไม่ยืนยันการบันทึกรายการหรือการจัดหน้าจอในเบราว์เซอร์

ให้เจ้าของโปรเจกต์เปิด [Authentication ใน Firebase Console](https://console.firebase.google.com/project/projectmoneymate/authentication): กด **Get started** หากยังไม่ได้เริ่ม แล้วเลือก **Sign-in method → Anonymous → Enable → Save** จากนั้นลองเชื่อมต่อในแอปอีกครั้ง

หากต้องการสร้าง options ใหม่หรือเพิ่มแพลตฟอร์มอื่น สามารถใช้ [FlutterFire CLI ตามคู่มือ Firebase](https://firebase.google.com/docs/flutter/setup) หลังติดตั้ง Firebase CLI และลงชื่อเข้าใช้ด้วยบัญชีที่มีสิทธิ์:

```sh
firebase login
dart pub global activate flutterfire_cli
flutterfire configure --project=projectmoneymate --platforms=android,web
```

คำสั่ง configure จะสร้าง options สำหรับแอปที่ลงทะเบียนจริง แล้วแทนที่ `lib/firebase_options.dart` ตรวจว่าเลือกโปรเจกต์และแพ็กเกจ Android ที่ระบุข้างต้น

`DefaultFirebaseOptions.currentPlatform` เลือกค่าจาก Web เมื่อรันในเบราว์เซอร์ และเลือกค่า Android เมื่อรันบน Android ค่า `measurementId` เก็บตาม config แต่ยังไม่มีการเพิ่มแพ็กเกจหรือเรียกใช้ Firebase Analytics

ใน [Firebase Console](https://console.firebase.google.com/project/projectmoneymate/overview) เปิด **Authentication → Sign-in method → Anonymous** และสร้าง **Cloud Firestore database** ใน production mode จากนั้นตรวจและติดตั้งกฎสิทธิ์ที่เหมาะสมก่อนทดลองบันทึก แอปใช้ anonymous UID เป็นเจ้าของข้อมูลที่:

```text
users/{uid}/transactions/{transactionId}
```

เอกสารยังใช้ schema เดิม 5 ฟิลด์: `title`, `amountSatang`, `type`, `category`, `date` ส่วน ID อยู่ในชื่อเอกสาร ไม่ได้เพิ่มฟิลด์ ID การเพิ่ม History ไม่ได้ย้ายข้อมูลหรือเปลี่ยนชื่อฟิลด์ให้เหมือนตัวอย่างในแชต

`FirestoreService` อ่าน stream พร้อม metadata เพื่อแสดงว่ากำลังใช้ข้อมูล cache หรือมีรายการรอยืนยันการเขียน หากอ่านหรือเริ่มระบบล้มเหลวจะแสดงข้อผิดพลาดและปุ่มลองอีกครั้ง ไม่มีการ seed ข้อมูลตัวอย่างเข้า Firestore

Anonymous account เป็นตัวตนของการติดตั้ง/เซสชันนี้ การถอนติดตั้ง ล้างข้อมูล หรือออกจากบัญชีอาจทำให้เข้าถึงข้อมูลเดิมไม่ได้ ฟีเจอร์บัญชีถาวรและการเชื่อมบัญชียังไม่ได้ทำ

## กฎและการตรวจสอบ

`firestore.rules` ใน workspace อนุญาตให้อ่าน สร้าง แก้ไข และลบรายการได้เฉพาะเจ้าของ UID โดยการสร้าง/แก้ไขยังตรวจชื่อ จำนวนเงิน ประเภท หมวดหมู่ และวันที่ ผู้ใช้แจ้งว่าอัปเดตกฎใน Console แล้ว; เซสชันนี้ยังไม่ได้ตรวจเอกสารกฎ remote หรือยืนยันการเขียนข้อมูลผู้ใช้จริง

ก่อนใช้การลบและงบประมาณกับข้อมูลจริง ให้เจ้าของโปรเจกต์เปิด [Firebase Console](https://console.firebase.google.com/project/projectmoneymate/overview) → **Firestore Database → Rules** เปรียบเทียบกับ `firestore.rules` แล้วอัปเดต/รวมกฎให้ตรงและกด **Publish** โดยคงกฎของคอลเลกชันอื่นไว้ เส้นทางรายการต้องมี `allow delete: if isOwner(userId);` และต้องมี match สำหรับ `users/{userId}/budgets/{monthId}` ที่อนุญาตเจ้าของอ่าน/สร้าง/แก้ไขพร้อมตรวจ 3 ฟิลด์ รหัสเดือน จำนวนเต็มสตางค์ และเวลาเซิร์ฟเวอร์ การจำกัดฟิลด์/ชนิดอ้างอิง [คู่มือ Firestore Rules](https://firebase.google.com/docs/firestore/security/rules-fields) ยังไม่ได้ทดสอบกฎด้วย Firebase Emulator ทางการหรือยืนยันการเผยแพร่ remote ในรอบนี้

หลังเตรียม dependencies แล้ว รัน:

```sh
flutter test --no-pub
flutter analyze --no-pub
flutter build web --no-pub
```

`--no-pub` ใช้ dependencies ที่ดาวน์โหลดไว้แล้ว การทดสอบในเครื่องครอบคลุมการคำนวณ จำนวนเงิน validation ฟอร์มสำเร็จ/ล้มเหลว การกดซ้ำ การกรองข้ามเดือน/ปี การค้นหา การแก้ไขที่คง ID/เวลา การยกเลิก/ล้มเหลว/timeout ของการลบ stream และยอด Dashboard หลังแก้ไข/ลบ รวมถึงการแปลงเอกสารและ Firestore service ผ่าน `fake_cloud_firestore` การตรวจ History ใช้ข้อมูล demo/fake ไม่ได้แก้ไขหรือลบรายการของผู้ใช้บน Firebase จริง การทดสอบ fake ไม่ได้ยืนยัน security rules, Authentication หรือการอ่าน/เขียนบน Firebase จริง ต้องตรวจเส้นทางเหล่านี้แยกหลังตั้งค่าบัญชีและแอปสำเร็จ

ผลตรวจหลังปรับหน้าตา วันที่ 11 พฤศจิกายน 2026: ชุดทดสอบ VM ผ่าน **142 รายการ**, `flutter analyze --no-pub` ไม่พบปัญหา และ build เว็บกับ Android debug APK สำเร็จ ตรวจภาพบน Android emulator **Pixel_10 (1080×2424)** ทั้งหน้าหลัก ประวัติ สถิติ งบและฟอร์ม รวมปุ่มซ่อนยอดและขนาดอักษร 1.3 เท่า แล้วคืนขนาดอักษรเดิม ตรวจจอกว้าง 1000×900 เพิ่มด้วย widget render ที่โหลดฟอนต์จริง ไฟล์ APK ปกติอยู่ที่ `build/app/outputs/flutter-apk/app-debug.apk`

การตรวจรอบนี้ครอบคลุมงบศูนย์/ว่าง/หนึ่งสตางค์ เกณฑ์ 80%/ครบวงเงิน/เกินงบ การสลับเดือนที่ไม่แสดงข้อมูลเก่า validation ข้อผิดพลาด/timeout การกดซ้ำ การบันทึกที่กลับมาหลังมีหน้าอื่นเปิดทับ และจอ 320 พิกเซลที่ขยายตัวอักษร 2 เท่าพร้อมคีย์บอร์ด ตรวจคอมเมนต์แล้วว่าครบไฟล์ Dart และคงโค้ดเดิมในไฟล์ที่แก้เฉพาะคำอธิบาย

เพิ่มการทดสอบการซ่อนยอดและ semantics การคงสถานะข้ามแท็บ/ข้อมูลใหม่ การเปลี่ยนเงินที่ตรงสตางค์ การลดแอนิเมชัน และเฟรมเริ่มต้น Android ที่ยังมีขนาดศูนย์ ภาพตัวอย่างอยู่ใน `build/ui-*-android.png` และ `build/ui-wide.png` ส่วน APK ส่งมอบ build จาก `lib/main.dart` ตามปกติ แยกจาก entrypoint ตัวอย่างชั่วคราวที่ใช้ตรวจ UI

การตรวจงบ สถิติ CRUD และภาพรอบนี้ใช้ demo/fake ไม่ได้สร้าง แก้ไข หรือลบข้อมูลของผู้ใช้บน Firebase จริง ผู้ใช้แจ้งว่าอัปเดตกฎแล้ว แต่การยืนยัน cloud write จริงยังต้องทดสอบในแอปกับบัญชีของตน ส่วนชุดทดสอบเฉพาะ Chrome ก่อนหน้านี้ยังไม่ได้ยืนยันว่าผ่านในสภาพแวดล้อมนี้
